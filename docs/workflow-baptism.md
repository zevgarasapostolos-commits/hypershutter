# Workflow μοντάζ βάφτισης: οργάνωση υλικού → highlights → ροή → XML για Premiere

Ο οδηγός περιγράφει όλη τη διαδικασία που ακολουθήθηκε σε μια σειρά από βαφτίσεις, από τη στιγμή που φτάνει το raw υλικό μέχρι την παράδοση των XML στο Premiere. Είναι γραμμένος ώστε άλλο εργαλείο ή άλλος βοηθός να μπορεί να τον αναπαράγει χωρίς να έχει δει τη συζήτηση. Κάθε κανόνας που ακολουθεί προέρχεται είτε από ρητή οδηγία του μοντέρ είτε από σύγκριση με το δικό του διορθωμένο μοντάζ. Το «γιατί» σημειώνεται όπου βοηθάει.

Οι γάμοι ακολουθούν τις ίδιες αρχές. Οι διαφορές τους είναι στο Παράρτημα Ε.

---

## 0. Τι παραδίδεται και τι ΔΕΝ κάνουμε

**Παραδοτέα, μέσα στον φάκελο της βάφτισης:**

1. Οργανωμένοι φάκελοι με αριθμημένες κατηγορίες, ένα αρχείο `00 ΕΥΡΕΤΗΡΙΟ ΠΛΑΝΩΝ.md` και ένας φάκελος `00 CONTACT SHEETS/`.
2. `<NNN> highlights.xml`: μουσικό βίντεο ~3:10 (190.52″) πάνω στο τραγούδι-πρότυπο.
3. `<NNN> ροή.xml`: όλη η τελετή σε συνέχεια, με intro, κατήχηση, μυστήριο, τέλος (και χορούς, αν υπάρχουν).
4. `music/`: αντίγραφο του τραγουδιού, ώστε το XML να μη δείχνει έξω από τον φάκελο.
5. `<NNN> highlights - preview (για έλεγχο).mp4` και `<NNN> ροή - preview (για έλεγχο).mp4`: 960×540, μόνο για έλεγχο.

Και τα δύο XML είναι **FCP7 xmeml v4**, sequence **3840×2160, 25 fps**.

**Τι ΔΕΝ κάνουμε, ποτέ (ρητή οδηγία):**

- **Μόνο κόψιμο και ράψιμο.** Όχι χρώμα, Lumetri, εφέ, Warp Stabilizer, overlays, τίτλους ή μεταβάσεις εικόνας. Αυτά τα κάνει ο μοντέρ.
- Η μόνη «επέμβαση» που επιτρέπεται στο XML είναι:
  - **Time Remap** (slow-mo στα highlights).
  - **Scale 200%** σε κλιπ 1080p, για να γεμίζουν το 4K.
  - **Constant Power** fades στον **ήχο**.
- Τα **Impact Dissolve** τα βάζει ο ίδιος. Εμείς αφήνουμε μόνο **marker** στο σημείο.
- Δεν πειράζουμε άλλα ανοιχτά projects στο Premiere.
- Δουλεύουμε στο background. Πλήρη έλεγχο της οθόνης παίρνουμε μόνο με άδεια και μόνο όπου είναι αναπόφευκτο.
- Όταν ρωτάει «μπορείς να κάνεις Χ;», συχνά εννοεί μόνο «γίνεται;». Απαντάμε πρώτα και ενεργούμε όταν πει «πάμε».
- Όταν προσθέτουμε κάτι σε υπάρχον project, μπαίνει **νέο sequence στο ίδιο project**, όχι νέο project. Νέο project φτιάχνουμε μόνο όταν το ζητήσει.

## 1. Εργαλεία

| Εργαλείο | Χρήση |
|---|---|
| `ffprobe` / `ffmpeg` | Metadata, καρέ, ήχος σε raw PCM, preview. Η έκδοση που χρησιμοποιήθηκε **δεν έχει `drawtext`**, οπότε τα labels μπαίνουν με OpenCV ή ImageMagick. |
| ImageMagick `montage` | Contact sheets κατά την οργάνωση. |
| Python 3 (venv) + `numpy`, `opencv-python` | Μετρήσεις κίνησης, συγχρονισμός, φύλλα ελέγχου, σχέδιο ροής, XML. |
| `mlx-whisper` (Apple Silicon), μοντέλο `mlx-community/whisper-large-v3-turbo` | Μεταγραφή των ελληνικών της τελετής. |
| Premiere Pro | Ο μοντέρ εισάγει τα XML (File → Import). |

Όλα τα ενδιάμεσα αρχεία (cache ήχου, motion, transcripts, φύλλα ελέγχου, preview segments) μένουν σε φάκελο εργασίας **εκτός** του φακέλου της βάφτισης. Μέσα στη βάφτιση γράφονται μόνο τα παραδοτέα.

## 2. Πώς φτάνει το υλικό

Τυπικός φάκελος: `/Volumes/T7/<NNN> Β<dd-mm-yyyy> [Β|Γ]/` (ή `/Volumes/T7 1/...`).

| Υποφάκελος | Τι είναι | Ονόματα |
|---|---|---|
| `cam apos` (ή `camera`, `apos`) | Κύρια κάμερα, 4K50 H.264. Το ρολόι της είναι **λάθος** (§3.2). | `C####.MP4` |
| `cam dim` (ή `dim`, `CLIP`, `CLIP1/2`) | Δεύτερη κάμερα (Sony, π.χ. A7IV). Το ρολόι είναι σωστό ή σχεδόν σωστό. Έχει `.XML` sidecar. | `C6###.MP4` |
| `drone` | DJI, 4K HEVC. **Η τοπική ώρα είναι μέσα στο όνομα αρχείου.** | `DJI_YYYYMMDDHHMMSS_NNNN_D.MP4` (+ `.LRF`/`.SRT`) |
| `sound` (όχι πάντα) | Wireless mic στον παπά (DJI Mic). Μια εγγραφή μπορεί να συνεχίζεται σε δεύτερο αρχείο. | `DJI_01_YYYYMMDD_HHMMSS.WAV`, `DJI_02_…` |

**Παγίδες:**

- Υπάρχουν **δύο δίσκοι με όνομα T7**. Όποιος συνδεθεί δεύτερος γίνεται `T7 1`, οπότε οι απόλυτες διαδρομές αλλάζουν από μέρα σε μέρα. Βρίσκουμε τον φάκελο κάθε φορά (`ls -d /Volumes/T7*/<NNN>*`) και δεν τον «καρφώνουμε».
- Αγνοούμε τα αρχεία `._*` (AppleDouble).
- Ένας φάκελος `CLIP2` **δεν σημαίνει απαραίτητα δεύτερη κάμερα**. Αν η αρίθμηση συνεχίζει χωρίς κενό, με ίδιο codec και ίδια ανάλυση, είναι η ίδια κάμερα σε άλλη μέρα ή άλλη κάρτα.
- Μπορεί να **μην υπάρχει mic**. Το ψάχνουμε σε όλους τους δίσκους (`DJI_0*` με την ημερομηνία) και, αν δεν βρεθεί, ρωτάμε. Σε μία βάφτιση ο μοντέρ επιβεβαίωσε ότι δεν υπήρχε mic, οπότε όλος ο ήχος της τελετής ήρθε από την κάμερα (§6.7).
- **Σχεδόν κάθε κλιπ της κύριας κάμερας ξεκινά με 3–6″ όπου η κάμερα κοιτάει το πάτωμα**, γιατί πατάει REC ενώ περπατάει. Ένα καρέ στην αρχή του κλιπ δεν λέει τίποτα για το περιεχόμενο.

# ΦΑΣΗ Α — Οργάνωση υλικού

## 3.1 Ανάγνωση αρχείων και ωρών

Για κάθε MP4 διαβάζουμε διάρκεια και `creation_time` (παράλληλα, ~10 διεργασίες):

```bash
find "cam apos" "cam dim" drone -iname '*.MP4' ! -name '._*' | sort > all.txt
xargs -a all.txt -P 10 -d '\n' -I{} sh -c \
 'o=$(ffprobe -v quiet -show_entries format=duration:format_tags=creation_time -of default=nw=1 "{}" | tr "\n" "|"); printf "%s\t%s\n" "{}" "$o"' > meta.txt
```

Μετά, σε Python:

1. Εξάγουμε `duration` και `creation_time` (τα πρώτα 19 χαρακτήρες, `%Y-%m-%dT%H:%M:%S`).
2. Ταξινομούμε χρονολογικά.
3. Τυπώνουμε ανά κάμερα το πλήθος, την πρώτη και την τελευταία ώρα, και τα συνολικά λεπτά.
4. Βγάζουμε χωριστή λίστα με τα **κλιπ ≥ 60″**. Αυτά είναι σχεδόν πάντα τα masters της τελετής (ροή) και οι χοροί.

Για το μοντάζ (Φάση Β) φτιάχνεται πλουσιότερος κατάλογος `media.json`, με ένα entry ανά clip (κλειδί το όνομα χωρίς `.MP4`):

```bash
ffprobe -v error -show_entries format=duration:format_tags=creation_time:stream=codec_type,codec_name,width,height,r_frame_rate,pix_fmt -of json <file>
```

Πεδία: `path`, `folder`, `dur`, `ctime`, `w`, `h`, `fps`, `pix`, `codec`, `audio`. Αγνοούμε video streams `mjpeg` (thumbnail).

Ελέγχουμε και τα formats: π.χ. 249 κλιπ ήταν `3840×2160 50p` και 18 ήταν `1920×1080 25p`. Τα 1080p θα χρειαστούν Scale 200% στο XML.

## 3.2 Διόρθωση ρολογιού

Το `creation_time` γράφεται με «Z», αλλά δεν είναι πάντα πραγματικό UTC. Ορίζουμε **μία κοινή «τοπική ώρα» (wall clock)** για όλες τις πηγές:

| Πηγή | Πώς βγαίνει η τοπική ώρα |
|---|---|
| **Drone** | Η ώρα στο **όνομα αρχείου** είναι τοπική και αξιόπιστη (`DJI_20261011163207…` = 16:32:07). Το `creation_time` του είναι UTC, δηλαδή ~3 ώρες πίσω το καλοκαίρι. |
| **Δεύτερη κάμερα** | `creation_time` + διαφορά ζώνης: **+3 ώρες (θερινή ώρα Ελλάδας, μέχρι την τελευταία Κυριακή του Οκτωβρίου), +2 ώρες (χειμερινή)**. Πάντα ελέγχουμε την ημερομηνία. Μπορεί να έχει και μικρό λάθος: +44″ σε μία βάφτιση, ~24′ σε άλλη. |
| **Κύρια κάμερα** | Το ρολόι είναι λάθος κατά ώρες. Έχει βρεθεί **+14:00** στις περισσότερες βαφτίσεις, αλλά και +14:02, +12:57 και ~11 ώρες σε άλλες. **Το υπολογίζουμε κάθε φορά.** |

**Μέθοδος υπολογισμού του offset της κύριας κάμερας:**

1. **Χοντρή εκτίμηση.** Ο στολισμός και τα εξωτερικά της εκκλησίας γίνονται συνήθως λίγο πριν ή γύρω από τις πτήσεις του drone, και η τελετή αρχίζει στην ώρα που είχε οριστεί. Βρίσκουμε το ακέραιο πλήθος ωρών που φέρνει την κάμερα στο ίδιο παράθυρο με το drone.
2. **Ακριβής τιμή από τη δεύτερη κάμερα, που έχει σωστό ρολόι.** Βρίσκουμε ένα γεγονός που το τράβηξαν και οι δύο. Παράδειγμα: η κατάδυση σε κοντινό από τη B πρέπει να πέφτει **μέσα** στο master της κατάδυσης σε πλατύ από την A. Το ίδιο ισχύει για τον μπαμπά που δακρύζει στην αρχή της κατήχησης, τον χορό, το ζευγάρι στο τέμπλο.
3. **Επιβεβαίωση με 2–3 ανεξάρτητα σημεία.** Σε μία περίπτωση το offset υπολογίστηκε **μόνο από το drone** και βγήκε 16 λεπτά λάθος (+13:44 αντί για +14:00). Η δεύτερη κάμερα το διόρθωσε.
4. Για ακρίβεια καρέ (μόνο στη Φάση Β) χρησιμοποιούμε **συγχρονισμό ήχου** (GCC-PHAT, §4.5).

Όλες οι ώρες στο ευρετήριο και στα contact sheets είναι **διορθωμένες**. Στην κορυφή του ευρετηρίου γράφουμε ρητά το offset και με ποια σημεία επιβεβαιώθηκε.

Στη Φάση Β ο κώδικας είναι:

```python
def wall(c):   # epoch seconds σε τοπική ώρα
    t = datetime.fromisoformat(media[c]["ctime"].replace("Z", "+00:00")).timestamp()
    return t + (14*3600 if c < "C6" else 3*3600)      # A: +14h, B: +3h (+ μικρό offset της B αν βρεθεί)
T0 = wall("<πρώτο master κατήχησης>"); rel = lambda c: wall(c) - T0
```

## 3.3 Καρέ ανά κλιπ

Τρία καρέ ανά κλιπ, **ποτέ ένα**. Το ένα καρέ ήταν η αιτία σοβαρών λαθών ταξινόμησης, ακριβώς επειδή τα κλιπ ξεκινούν με την κάμερα στο πάτωμα.

| Διάρκεια κλιπ | Θέσεις καρέ |
|---|---|
| ≥ 4″ | 15%, 50%, 85% |
| 1.5–4″ | 30%, 70% |
| < 1.5″ | 50% |

Ελάχιστο t = 0.2″.

```bash
ffmpeg -v quiet -ss <t> -i "<file>" -frames:v 1 -vf scale=300:-1 -y "frames/<clip>_<i>.jpg" </dev/null
```

Τρέχουν παράλληλα (`xargs -P 5`) και είναι επαναλήψιμα: παραλείπεται όποιο υπάρχει ήδη (`[ -s out.jpg ] ||`). Στο τέλος ελέγχουμε ότι δεν λείπει κανένα.

## 3.4 Contact sheets

**Φύλλα εργασίας, για την ταξινόμηση.** Όλα τα καρέ μπαίνουν σε **διορθωμένη χρονολογική σειρά**, 48 ανά φύλλο:

```bash
montage -label '<clip>.<i> <HH:MM> <dur>s' frame1.jpg -label ... frameN.jpg \
  -tile 8x6 -geometry 260x146!+2+2 -pointsize 14 -background black -fill yellow sheet_00.jpg
```

Στα drone το label γράφεται `DJI<NNNN>`. Ο βοηθός **κοιτάει κάθε φύλλο ένα-ένα** και αποφασίζει την κατηγορία κάθε κλιπ από το περιεχόμενο **και** την ώρα. Η χρονολογική σειρά με σωστές ώρες είναι αυτό που κάνει την ταξινόμηση αξιόπιστη, γιατί τα γεγονότα της μέρας φαίνονται ως συνεχόμενα μπλοκ.

**Φύλλα παράδοσης, ένα ανά φάκελο,** στο `00 CONTACT SHEETS/<NN>.jpg` (π.χ. `08a.jpg`). Περιέχουν το μεσαίο καρέ κάθε κλιπ (`_1`, αλλιώς `_0`):

```bash
montage ... -tile 7x -geometry 280x158!+2+2 -pointsize 15 -background black -fill yellow "00 CONTACT SHEETS/08a.jpg"
```

Για τα μεγάλα masters, όταν χρειάζεται να δούμε τι έχουν μέσα, φτιάχνουμε **filmstrips**: μία γραμμή ανά κλιπ με label, ακολουθούμενη από Ν καρέ σε ίσα διαστήματα ή κάθε 5–20″. Στα καρέ γράφεται ο χρόνος πηγής με `cv2.putText`.

## 3.5 Κατηγορίες και ονόματα φακέλων

**Κανόνες ονοματοδοσίας:**

- Διψήφιος αριθμός μπροστά (`01`, `02`, …) **με τη σειρά που έγιναν τα πράγματα εκείνη τη μέρα**. Η σειρά αλλάζει από βάφτιση σε βάφτιση: σε μία ήρθαν πρώτα τα εξωτερικά, σε άλλη ο στολισμός.
- Ονόματα **στα ελληνικά, με κεφαλαία**. Στις πρώτες βαφτίσεις είχαν χρησιμοποιηθεί λατινικά (`01 STOLISMOS`), αλλά το καθιερωμένο πλέον είναι ελληνικά.
- Διαχωριστικό ` — ` (em dash με κενά) ανάμεσα σε γεγονός και τύπο: `08 ΚΑΤΗΧΗΣΗ — ΡΟΗ`.
- Η **B-ROLL εκδοχή ενός φακέλου ΡΟΗ** παίρνει τον ίδιο αριθμό με **`a`**: `08` / `08a`, `09` / `09a`.
- Παρενθέσεις για υπόδειξη περιεχομένου (`03 ΛΕΠΤΟΜΕΡΕΙΕΣ (ΡΟΥΧΑ, ΛΑΜΠΑΔΑ, ΛΑΔΟΠΑΝΟ)`) και `&` για συνδυασμούς (`ΣΤΟΛΙΣΜΟΣ & CANDY BAR`).
- Κατηγορίες που δεν υπάρχουν σε μια βάφτιση δεν φτιάχνονται. Όταν η μέρα έχει κάτι ιδιαίτερο, προστίθεται φάκελος: `ΠΑΙΔΙΑ — FACE PAINTING`, `ΜΟΥΣΙΚΟΙ`, `ΦΩΤΟΓΡΑΦΗΣΗ ΓΟΝΕΩΝ`, `ΟΙΚΟΓΕΝΕΙΑΚΗ ΦΩΤΟΓΡΑΦΗΣΗ ΣΤΟ ΠΑΡΚΟ`.
- `99 ΑΧΡΗΣΤΑ` μόνο για κλιπ πραγματικά άχρηστα (μαύρο, πάτωμα από την αρχή ως το τέλος). Σπάνια χρειάζεται.

**Τυπική λίστα (με τη σειρά μιας πραγματικής μέρας):**

```
01 ΣΤΟΛΙΣΜΟΣ & CANDY BAR
02 ΕΞΩΤΕΡΙΚΑ ΕΚΚΛΗΣΙΑΣ
03 ΛΕΠΤΟΜΕΡΕΙΕΣ (ΡΟΥΧΑ, ΛΑΜΠΑΔΑ, ΛΑΔΟΠΑΝΟ)      ← ή «ΛΑΔΙΚΑ, ΡΟΥΧΑ, ΛΑΜΠΑΔΕΣ»
04 ΕΣΩΤΕΡΙΚΟ ΕΚΚΛΗΣΙΑΣ
05 DRONE                                       ← όλα τα drone μαζί, ό,τι ώρα κι αν είναι
06 ΠΟΡΤΡΕΤΑ ΟΙΚΟΓΕΝΕΙΑΣ (ΠΡΙΝ)                  ← ΣΤΗΜΕΝΑ
07 ΑΦΙΞΗ ΚΑΛΕΣΜΕΝΩΝ                             ← ΑΥΘΟΡΜΗΤΑ
08 ΚΑΤΗΧΗΣΗ — ΡΟΗ
08a ΚΑΤΗΧΗΣΗ — B-ROLL
09 ΜΥΣΤΗΡΙΟ — ΡΟΗ
09a ΜΥΣΤΗΡΙΟ — B-ROLL
10 ΚΕΡΑΣΜΑ ΕΞΩ ΑΠΟ ΤΗΝ ΕΚΚΛΗΣΙΑ                 ← αν υπάρχει μεγάλο συνεχές πλάνο: «10 ΚΕΡΑΣΜΑ — ΡΟΗ» + «10a ΚΕΡΑΣΜΑ & ΚΟΣΜΟΣ»
11 ΔΕΞΙΩΣΗ — ΧΩΡΟΣ & ΤΡΑΠΕΖΙΑ
12 ΦΩΤΟΓΡΑΦΗΣΗ ΓΟΝΕΩΝ
13 ΠΑΙΔΙΑ — FACE PAINTING
14 ΜΟΥΣΙΚΟΙ
15 ΧΟΡΟΣ
```

**Διορθώσεις που έδωσε ο μοντέρ στην ταξινόμηση:**

1. Ήθελε κατηγορίες «για να τα βρίσκω πιο εύκολα»: στολισμός, εξωτερικά εκκλησίας, μυστήριο κ.λπ.
2. Τα **πορτρέτα πριν τη βάφτιση** μπαίνουν σε **ξεχωριστό φάκελο**.
3. Τα **πορτρέτα θέλει σε διαφορετικό φάκελο από την άφιξη των καλεσμένων.** Το κριτήριο είναι αν το πλάνο είναι **στημένο** ή **αυθόρμητο**.
   - **Πορτρέτα** = ποζάρουν με το μωρό, συχνά στα σκαλιά: γονείς, νονοί, παππούδες, ομαδικές, το μωρό μόνο του.
   - **Άφιξη** = κόσμος που φτάνει, χαιρετούρες, κουβέντες, παιδιά που παίζουν.
4. Η κατήχηση και το μυστήριο χωρίζονται σε **τέσσερις** φακέλους: ΚΑΤΗΧΗΣΗ — ΡΟΗ, ΚΑΤΗΧΗΣΗ — B-ROLL, ΜΥΣΤΗΡΙΟ — ΡΟΗ, ΜΥΣΤΗΡΙΟ — B-ROLL. Πριν από αυτό υπήρξαν διαδοχικά δύο εκδοχές:
   - πρώτα **ένας** φάκελος «b-roll κατήχησης»,
   - μετά **δύο** φάκελοι: «b-roll κατήχησης» και «b-roll ροής».
5. «Πολλά τα έχεις κάνει λάθος». Πορτρέτα και b-roll της κατήχησης είχαν μπει στην ΑΦΙΞΗ, και ένα master της κατήχησης στο ΜΥΣΤΗΡΙΟ. Η αιτία ήταν το ένα καρέ ανά κλιπ και το ρολόι που δεν είχε διορθωθεί. Από τότε: **τρία καρέ ανά κλιπ και διορθωμένες ώρες, πάντα**.
6. «Οργάνωσέ τη με προσοχή και λεπτομερώς». Κάθε κλιπ ελέγχεται.
7. **Μετακίνηση, όχι αντιγραφή** («μετακίνησέ τα όλα στους αντίστοιχους φακέλους»). Τα αντίγραφα έπιαναν χώρο στον δίσκο, που ήταν σχεδόν γεμάτος. Όταν ζητά απλώς να βρούμε κάτι, του δίνουμε **λίστα** και δεν αντιγράφουμε.
8. Χρήσιμοι εντοπισμοί που ζήτησε κατά καιρούς: «ποιο είναι το πιο γενικό του στολισμού», «ποια είναι τα κοντινά με το λάδι στο χέρι της νονάς πριν την κολυμπήθρα». Το ευρετήριο πρέπει να βοηθάει σε τέτοιες ερωτήσεις, γι' αυτό κάθε φάκελος έχει περιγραφή.

## 3.6 ΡΟΗ ή B-ROLL

**ΡΟΗ** = τα **μεγάλα συνεχή πλάνα της κύριας κάμερας** (masters) κατά τη διάρκεια της τελετής. Γυρίζονται από σταθερή θέση και «γράφουν» την ακολουθία:

- Συνήθως **2–3 masters στην κατήχηση και 3–4 στο μυστήριο**.
- Διάρκεια **~1:30 έως ~10′** το καθένα (σίγουρα ≥ 60″).
- Χρονικά είναι **συνεχόμενα**: το επόμενο ξεκινά λίγα δευτερόλεπτα ή λεπτά μετά το τέλος του προηγούμενου.

**B-ROLL της ίδιας ενότητας** = ό,τι άλλο γυρίστηκε **μέσα στο χρονικό παράθυρο** αυτής της ενότητας:

- τα μικρά κλιπ της κύριας κάμερας ανάμεσα στα masters (πρόσωπα, αντιδράσεις, λάδι, γδύσιμο, ντύσιμο, σταυρός, παιδιά με λαμπάδες),
- **όλα** τα κλιπ της δεύτερης κάμερας εκείνης της ώρας. Συχνά η B δουλεύει αποκλειστικά cutaways όσο η A γράφει το master.

**Παράθυρα, πάντα με διορθωμένες ώρες:**

- **Κατήχηση** = από την αρχή του πρώτου master της κατήχησης (συνήθως στον νάρθηκα, στην είσοδο ή έξω) ως το τέλος του τελευταίου. Το b-roll της κατήχησης είναι έξω από την εκκλησία, «εκεί που διαβάζει ο παπάς το μωρό», **όχι μέσα στο μυστήριο**.
- **Μυστήριο** = από το πρώτο master στην κολυμβήθρα ως την έξοδο για το κέρασμα.

**Παγίδες:**

- Κλιπ λίγο πριν την αρχή του παραθύρου μπορεί να είναι ήδη b-roll κατήχησης (ο παπάς βγαίνει, η μαμά φέρνει το μωρό) και όχι άφιξη. Κρίνουμε από περιεχόμενο **και** ώρα.
- Ο μοντέρ ρώτησε «τσέκαρες και τα μεγάλα αρχεία; μήπως έχω τραβήξει κάτι και εκεί;». Μέσα στα masters μπορεί να υπάρχουν σπασίματα σε κοντινό μωρό ή pan στον κόσμο. Αν ζητηθεί, τα σημειώνουμε με in/out σε χρόνο πηγής, όπως φαίνονται στο source monitor.
- Τα κλιπ της B με κίνηση και κούνημα μένουν στον φάκελο B-ROLL. Το αν θα χρησιμοποιηθούν κρίνεται στο μοντάζ (§6.6).

## 3.7 Μετακίνηση και επαλήθευση

1. Φτιάχνουμε σε Python ένα `OrderedDict` κατηγορία → λίστα clips. Χρήσιμοι βοηθοί: `R(a, b)` για εύρος αριθμών, `L(...)` για μεμονωμένα.
2. **Πριν μετακινήσουμε οτιδήποτε**, ελέγχουμε τρία πράγματα:

# ΦΑΣΗ Β — Ανάλυση για μοντάζ

## 4.1 Ήχος: mic ή κάμερα;

- **Υπάρχει mic** (`sound/DJI_0x_*.WAV`): ενώνουμε τα αρχεία της ίδιας εγγραφής (DJI_01 + DJI_02 που τη συνεχίζει) σε ένα συνεχές σήμα. Αυτό γίνεται ο «χρονικός άξονας» της τελετής.
- **Δεν υπάρχει mic**: ο ήχος της τελετής είναι ο ήχος της κάμερας που φαίνεται κάθε στιγμή.
  - Ελέγχουμε αν η κάμερα έχει ξεχωριστό κανάλι mic: συγκρίνουμε τα c0 και c1 με `volumedetect` και correlation. Συσχέτιση ~0.6 και ίδια στάθμη σημαίνει ότι είναι το ίδιο ενσωματωμένο mic.
  - Μετράμε τη στάθμη κάθε κομματιού (`volumedetect`), ώστε να ξέρουμε πού χρειάζεται να μειωθεί στο preview.

## 4.2 Μεταγραφή των masters

Πρώτο πέρασμα:

```python
import mlx_whisper
# ήχος: ffmpeg -i <master> -map 0:a:0 -ac 1 -ar 16000 tx/<c>.wav
r = mlx_whisper.transcribe(wav, path_or_hf_repo="mlx-community/whisper-large-v3-turbo", language="el",
        word_timestamps=True, condition_on_previous_text=False,
        initial_prompt="Ακολουθία του Αγίου Βαπτίσματος. Του Κυρίου δεηθώμεν. Αποτάσσομαι. Πιστεύω εις ένα Θεόν, Πατέρα, παντοκράτορα.")
# αποθήκευση: λίστα από {start, end, text, words:[(s,e,w)]}
```

Δεύτερο πέρασμα, για καθαρότερο αποτέλεσμα, ιδίως με ήχο κάμερας:

- `-af highpass=f=100,loudnorm`,
- **ξεχωριστό λειτουργικό prompt ανά master** με τις φράσεις που αναμένονται σε αυτό το τμήμα (π.χ. «Επί τω ονόματί σου, Κύριε… Επιτιμά σοι Κύριος, διάβολε» / «Αποτάσσῃ τῷ Σατανᾷ; Αποτάσσομαι. Εμφύσησον και έμπτυσον αυτώ…» / «Βαπτίζεται ο δούλος του Θεού <όνομα>…»),
- `no_speech_threshold=0.8`.

Τυπώνουμε τα segments με χρόνους. Διαβάζοντάς τα σημειώνουμε τι είναι **λειτουργικό κείμενο** και τι **κουβέντα εκτός τελετής** (§6.2). Τα δύσκολα σημεία τα ξαναμεταγράφουμε στοχευμένα.

## 4.3 Μετρήσεις κίνησης (για κάθε κλιπ εκτός των πολύ μεγάλων χορών)

Ανάλυση 10 fps σε γκρι 320×180 (`-hwaccel videotoolbox`). Για κάθε καρέ:

- `shift`: η μετατόπιση από το προηγούμενο καρέ, με `cv2.phaseCorrelate` και Hanning window. Μετράει πόσο κουνιέται η κάμερα.
- `resid`: η μέση διαφορά μετά την ευθυγράμμιση. Αντιστοιχεί σε κίνηση μέσα στο κάδρο.
- `bright`: μέση φωτεινότητα. `sharp`: διασπορά Laplacian (εστίαση).

Αποθήκευση σε `motion/<clip>.npz`. Για κλιπ με λιγότερα από 3 καρέ γράφουμε μηδενικά. Αν ο πίνακας είναι μικρότερος από τον πυρήνα εξομάλυνσης, χρειάζεται fallback.

Παράγωγα μεγέθη:

- `jitter = |shift − smooth(shift, 5)|`: το «τρέμουλο», σε αντίθεση με την ομαλή κίνηση.
- **Κουνημένο δευτερόλεπτο** = `max(shift) > 6` ή `mean(jitter) > 0.8` μέσα στο δευτερόλεπτο. Με αυτό βρίσκουμε σταθερά παράθυρα για cutaways και τα κουνημένα κομμάτια των masters.

Για γρήγορη ανάλυση σε HEVC ή 10-bit μπορεί να γίνει decode μόνο των keyframes (`-skip_frame nokey`).

## 4.4 Drone: παράθυρα που ΚΙΝΟΥΝΤΑΙ

Ο μοντέρ είπε: «Θέλω τα πλάνα του drone να έχουν κίνηση, όχι κάτι σταθερά». Η αρχική βαθμολόγηση με κριτήριο τη σταθερότητα διάλεγε hover, που είναι λάθος.

1. Καρέ 5 fps, 160×90 γκρι, με Gaussian blur 5×5 → `dchg/<clip>.npy`.
2. Για κάθε παράθυρο διάρκειας L (σε δευτερόλεπτα πηγής) από το i ως το i+w:

```python
change     = mean(|frame[i] - frame[i+w]|)            # πόσο άλλαξε η εικόνα από αρχή σε τέλος (θέλουμε ΜΕΓΑΛΟ)
steadiness = std(διαφορές διαδοχικών καρέ σε ~6 σημεία)  # ομοιόμορφη ταχύτητα
j          = mean(jitter στο παράθυρο); whip = max(shift)
score = change / max(L, 0.5) - 4*j - 0.3*max(0, whip - 12) - 0.5*steadiness   # μεγαλύτερο = καλύτερο
```

3. Πάντα κοιτάμε και filmstrip για επιβεβαίωση. Προτιμάμε orbit γύρω από τον ναό, push ή πτήση μπροστά, flyover πάνω από την πόλη, reveal. Για το establishing πλάνο θέλουμε το **πιο ανοιχτό** κομμάτι (όλη η πόλη ή τα βουνά), όχι το σφιχτό πάνω στον ναό.

## 4.5 Συγχρονισμός ήχου (mic ↔ κάμερα, κάμερα B ↔ κάμερα A)

GCC-PHAT σε mono 4 kHz (`ffmpeg -ac 1 -ar 4000 -f f32le`, με cache):

```python
def gcc(a, b):
    n = 1 << int(np.ceil(np.log2(len(a) + len(b))))
    R = np.fft.rfft(a, n) * np.conj(np.fft.rfft(b, n)); R /= np.abs(R) + 1e-9
    return np.fft.irfft(R, n)
# τοπικό: ψάχνουμε το κλιπ x μέσα σε παράθυρο y[a:b] γύρω από την αναμενόμενη θέση (±25…60 s)
cc = gcc(y[a:b], x); L = b - a - len(x); v = cc[:L+1]; lag = argmax(v); snr = v[lag] / std(v)
pos = y0 + (a + lag) / SR
```

- **Με mic:** κάθε master συγχρονίζεται με το mic. Πρώτα κάνουμε global αναζήτηση, μετά τοπική εκλέπτυνση ±25″. Έτσι κάθε κομμάτι της ροής ορίζεται σε «χρόνο mic».
- **Κάμερα B:** η αναμενόμενη θέση βγαίνει από το ρολόι (§3.2). Συσχετίζουμε **μόνο το επικαλυπτόμενο κομμάτι** με το master (±8″). Τα αποτελέσματα με υψηλό SNR (≥ ~13) δίνουν το μικρό offset της B (π.χ. +44″), το οποίο μετά εφαρμόζουμε σε όλα τα κλιπ της.
- Πολύ μικρά κλιπ ή κλιπ που πέφτουν σε κενό ανάμεσα σε masters δεν συγχρονίζονται με ήχο. Τα τοποθετούμε με το διορθωμένο ρολόι και τα επαληθεύουμε με το μάτι.
- Η global αναζήτηση σε μικρά κλιπ δίνει ψεύτικες κορυφές. Γι' αυτό: πρώτα offset ρολογιού, μετά τοπικό παράθυρο.

**Slow-mo και σταθερότητα:**

- **Slow-mo μόνο σε λεπτομέρειες και τρυφερές κοντινές στιγμές** (φαγητό, διακόσμηση, λουλούδια, μαμά που φιλάει το μωρό). Ποτέ σε masters, πλήθος ή στημένες ομαδικές. Περίπου 18% των πλάνων.
- **Το περιεχόμενο μετράει περισσότερο από τη σταθερότητα.** Ο μοντέρ χρησιμοποιεί πλάνα που ένα φίλτρο κουνήματος θα έκοβε και τα σταθεροποιεί μόνος του. Τα πολύ μικρά κλιπ (~1″) είναι εντάξει για slots 0.9″. Σημειώνουμε τα κουνημένα αλλά καλά πλάνα, δεν τα πετάμε. Πετάμε μόνο τα **πολύ** κουνημένα.
  - Η αρχική οδηγία ήταν «τα πλάνα να είναι σταθερά, να μην κάνει πολλές διορθώσεις η κάμερα». Ισχύει ως προτίμηση ανάμεσα σε ισάξια πλάνα.

**Drone:**

- **Πάντα με κίνηση** και από το πιο ανοιχτό κομμάτι.

**Ρυθμός και σημεία:**

- Πριν τη βουτιά: **ένα πλάνο ~4″** αντί για δύο των 2″.
- Ύφος «τρυφερό», όπως στο πρότυπο.

## 6.2 Τι κρατάμε και τι κόβουμε από τα masters

Η μεταγραφή μάς λέει πού είναι τι. **Κρατάμε το τυπικό της τελετής και κόβουμε την κουβέντα που είναι εκτός τελετής.**

**ΚΡΑΤΑΜΕ:**

- «Εις το όνομα…» / **«Επί τω ονόματί σου…» (η πρώτη ευχή)** ως το «Αμήν» της.
- **Εξορκισμοί: μόνο ένα απόσπασμα ≤ ~10″** (π.χ. «Επιτιμά σοι ο Κύριος…») πάνω σε **2–3 σύντομα πρόσωπα** b-roll στο V1. Όχι 100″ γέφυρα με b-roll.
- **Αποτάσσομαι…** και **«εμφύσησον και έμπτυσον αυτώ… φύσηξε / φτύσε τρεις φορές κάτω»**. Ρητά: «εκεί που λέει ο παπάς φτύσε κάτω και φύσηξε πάνω, αυτά τα κρατάμε». Κόβουμε μόνο **μετά**, π.χ. στο «γύρνα προς Ανατολή».
- **Συντάσσομαι**, **Πιστεύω** (το Σύμβολο της Πίστεως), **Προσκυνώ**, η **ευχή με το όνομα**, το «Δόξα σοι».
  - Το Πιστεύω το λέει ο ανάδοχος σιγά, οπότε στο mic ακούγεται σαν κουβέντα, αλλά είναι τυπικό. Ο μοντέρ το κράτησε και πέρασε το σιγανό κομμάτι από Enhance Speech. Εμείς το είχαμε κόψει, λάθος.
- Μυστήριο:
  - «Ευλογημένη η Βασιλεία…» / ειρηνικά στην κολυμβήθρα.
  - Αγιασμός του ύδατος. Αφήνουμε το master να τρέξει ακόμα και 55″, αντί να κάνουμε γέφυρα.
  - Αλληλούια.
  - **Η συνεχής δράση χρίσμα → λάδωμα → ΒΟΥΤΙΑ → σφραγίς ΑΚΟΜΑ ΚΙ ΑΝ ο παπάς δίνει οδηγίες ενδιάμεσα.** Κόβουμε κουβέντα μόνο όταν δεν φαίνεται τίποτα τυπικό στην οθόνη.
  - «Όσοι εις Χριστόν» (ο κύκλος), το προκείμενο.
- **Ευαγγέλιο**, μόνο όταν ακούγεται καθαρά στο mic. Αν διαβάστηκε μακριά από το mic, ο μοντέρ το έκοψε, οπότε δεν το «μπαλώνουμε» με ήχο κάμερας. Χωρίς mic στη βάφτιση, κρατάμε τον ήχο της κάμερας αν είναι καθαρός.
- Η ευχή με το όνομα στο τέλος, «Εδικαιώθης…», η **Απόλυσις**.
- **Μετά την Απόλυση: οι μετάνοιες και τα φιλήματα στο χέρι του παπά**, μαζί με τις οδηγίες του, γιατί είναι δράση στην οθόνη. Και το «να ζήσει».

**ΚΟΒΟΥΜΕ:**

- Οδηγίες σε γονείς και νονούς («κράτα το έτσι», «τρεις μετάνοιες…»), κουβέντα πριν την έναρξη, κουβέντα για φωτογραφίες, επαναλήψεις του ίδιου ψαλμού.
- Μετά το «Όσοι εις Χριστόν»: το σιωπηλό κομμάτι του Αποστόλου, την Εκτενή και τις μακριές ευχές. Το τέλος **συμπυκνώνεται**.
- **Τα κουνημένα κομμάτια όπου η κάμερα αλλάζει θέση ΚΟΒΟΝΤΑΙ, δεν σκεπάζονται.** Το άλμα που μένει κρύβεται με 1–3 σύντομα cutaways (~1–3″ το καθένα). Όχι μακριές αλυσίδες από cutaways των 5.5″.
- Όταν ένα master ξεκινά κουνημένο, το **ξεκινάμε αργότερα** (π.χ. από το 5.9″ ή το 14″). Δεν το σκεπάζουμε.
- Μικροσκοπικές γέφυρες των 4–18″ («Ευλογημένη» 6″, «Μέγας εί» 18″, «Χιτώνα μοι» 12″, «Εβαπτίσθης» 4″) ο μοντέρ τις έσβησε όλες.

## 6.3 Σημεία κοπής

- Αρχή και τέλος κάθε κομματιού **σε καθαρό όριο πρότασης**, π.χ. ακριβώς στο «Εις το όνομα του Πατρός…». Τις ευχές τις τελειώνουμε **στο «Αμήν» τους**, όχι μέσα στην επόμενη.
- Χρησιμοποιούμε τα χρόνια λέξεων της μεταγραφής και μετά **«κουμπώνουμε» την κοπή στο πιο ήσυχο σημείο** σε ±0.2″:
  - φάκελος έντασης σε παράθυρα 0.1″ (`20·log10(rms)` ανά 400 δείγματα στα 4 kHz),
  - το ελάχιστο εξομαλυμένο σε 0.3″.

## 6.4 Γέφυρες: μόνο όπου η κάμερα ήταν σβηστή

- **Όχι γέφυρες στο V1 με b-roll πάνω στον ήχο του παπά.** Ο μοντέρ έσβησε όλες τις δικές μας: πρόσωπα πάνω στην ευχή του λαδιού, «λάδι στο νερό / Αλληλούια», απόλυση αφού είχε τελειώσει το master, κοντινά από το ντύσιμο, «Εδικαιώθης».
- Μόνο όταν **η κάμερα της ροής ήταν σβηστή** (γδύσιμο, ντύσιμο) μπαίνουν **10–35″ από το b-roll εκείνης της στιγμής στο V1, με τον ΔΙΚΟ ΤΟΥ ήχο κάμερας** (κλάμα μωρού, ατμόσφαιρα), όχι με τον ήχο του mic.
- Marker «κάμερα σβηστή — b-roll με δικό του ήχο (Impact Dissolve)» πριν, και «Impact Dissolve» μετά.
- Μια γέφυρα μπορεί να ενώνει δύο masters (π.χ. γδύσιμο ανάμεσα σε δύο masters). Ο μοντέρ καμιά φορά επιβραδύνει τέτοιο b-roll (nested + Warp, ~0.7×). Αυτό το κάνει ο ίδιος.

## 6.5 Cutaways (V2)

- **Κυρίως για να κρύψουν τις κοπές** (jump cuts). Περίπου τα μισά cutaways πέφτουν σε κοπή και ξεκινούν ~1.3–1.4″ πριν από αυτήν.
- Τα υπόλοιπα είναι αραιά, για ρυθμό: ~ένα κάθε 40–50″ στην κατήχηση, **λιγότερα στο μυστήριο**, με μεγάλα καθαρά διαστήματα. Μέσα στο μεγάλο master χρίσμα → βουτιά, ελάχιστα ή κανένα (σε μία βάφτιση κανένα για 2:20). Μερικά jump cuts μπορούν να μείνουν ακάλυπτα.
- **Τίποτα πάνω από τη βουτιά.** Ο κώδικας ελέγχει ότι κανένα V2 δεν επικαλύπτει το παράθυρο της κατάδυσης.
- **Κάθε b-roll χρησιμοποιείται ΜΙΑ φορά σε όλη τη ροή**, και το ίδιο ισχύει για όσα μπήκαν σε γέφυρες. Χρησιμοποιούμε **όσο περισσότερα διαφορετικά καλά b-roll γίνεται**: σε μία βάφτιση 19 από τα 69 b-roll της τελετής δεν είχαν χρησιμοποιηθεί από κανέναν μας.
- Διαλέγουμε **τις καλύτερες στιγμές** (χαμόγελα, αντιδράσεις, παιδιά) και όχι απλώς τις πιο σταθερές. Το παράθυρο όμως πρέπει να είναι σταθερό: το βρίσκουμε από το per-second shake (§4.3), αλλιώς αλλάζουμε κλιπ.
- Διάρκεια 2–7″, συνήθως ~3–3.5″.

Μορφή στον κώδικα:

```python
("AT", clip, src_in, master, master_time, dur)   # ξεκινά στη χρονική θέση master_time του master
("J",  clip, src_in, join_no, dur, pre)          # γύρω από την κοπή #join_no, ξεκινά pre″ πριν
```

## 6.6 Δικάμερο (κάμερα B)

- Η δεύτερη κάμερα γράφει παράλληλα, ιδίως στο **Πιστεύω** και στην **κολυμβήθρα**. Τη συγχρονίζουμε με ήχο και την κόβουμε **στον πραγματικό, συγχρονισμένο χρόνο της** στο V2, σαν multicam, ώστε η ίδια στιγμή να φαίνεται από δύο γωνίες. **Όχι** σαν cutaway εκτός χρόνου.
- **Μόνο όταν είναι σταθερή.** Ο μοντέρ έβγαλε κάθε κουνημένο κλιπ της B και κράτησε μόνο τα σταθερά. Αν όλη η B είναι κουνημένη, δεν κάνουμε δικάμερο. Ένα σταθερό κομμάτι της B με δυνατό περιεχόμενο μπορεί να μπει σαν πρόσωπο στα εξορκιστικά, αν πέφτει την ίδια ώρα (π.χ. ο μπαμπάς που δακρύζει).

## 6.7 Ήχος της ροής

**Με mic:**

- Στο **A1 μόνο το mic.** Ο ήχος κάμερας δεν χρησιμοποιείται στην τελετή. Στις κοπές μπαίνουν σύντομα constant-power crossfades.
- Στο κέρασμα ήχος κάμερας, με J-cut και crossfade ~12″ από το mic.

**Χωρίς mic:**

- Στο **A1 ο ήχος του master που φαίνεται.** Στα «F» (πρόσωπα πάνω σε απόσπασμα), ο ήχος του master συνεχίζει κάτω από τα πρόσωπα.

**Πάντα:**

- Γέφυρες και χοροί με τον δικό τους ήχο.
- **Μουσική** σε A2/A3 (stereo: srctrack 1 και 2). Στο intro από 0 έως ~92″, fade-out 15.9″. Στο τέλος μπαίνει κάτω από τις τελευταίες ευχές ή φράσεις (~3–16″ νωρίτερα, fade-in ~10″) και κλείνει με fade 1.2″.
- **Ευχές** (αν υπάρχει μεγάλο πλάνο): 5–6′ χωρίς ήχο, πάνω σε piano covers από τη βιβλιοθήκη του μοντέρ. Έχουν χρησιμοποιηθεί το «What Was I Made For» και μετά το «All of Me». Η μουσική μπαίνει ~3″ πριν τελειώσει η τελευταία φράση του mic.

## 6.8 Markers

Όλα τα markers μπαίνουν στο sequence:

- «ΤΙΤΛΟΣ» (8.36″).
- «ΚΑΤΗΧΗΣΗ — Impact Dissolve», «ΜΥΣΤΗΡΙΟ — Impact Dissolve».
- «κάμερα σβηστή — b-roll με δικό του ήχο (Impact Dissolve)» και «Impact Dissolve» στο τέλος κάθε γέφυρας.
- «ΒΟΥΤΙΑ».
- «ΕΥΑΓΓΕΛΙΟ — Impact Dissolve», «ΕΥΧΗ / ΑΠΟΛΥΣΗ — Impact Dissolve».

## 6.9 Χοροί (όταν υπάρχουν)

Ρητή οδηγία: «τους χορούς θέλω να τους βάλεις ολόκληρους στη ροή». Ακολουθούμε το πρότυπο του μοντέρ:

1. Τελετή → ~6″ drone → **σύντομο μοντάζ κεράσματος / δεξίωσης με μουσική, χωρίς πλάνα χορού** (τα πλάνα χορού των highlights αφαιρούνται, γιατί οι χοροί θα παίξουν ολόκληροι) → 1–2 drones **με κίνηση** ως το τέλος του τραγουδιού.
2. **Κάθε κλιπ χορού, το ένα μετά το άλλο, ΟΛΟΚΛΗΡΟ, με τον δικό του ήχο κάμερας**, με τη σειρά που γυρίστηκαν. Κόβουμε **μόνο 1–5″** στην αρχή ή στο τέλος, εκεί που η κάμερα σηκώνεται, κατεβαίνει ή κουνιέται. Τα βρίσκουμε με καρέ στην αρχή και στο τέλος κάθε κλιπ και με δείγμα κάθε 20″.
3. Κλιπ με τους μουσικούς ανάμεσα στους χορούς μένει στη χρονική του θέση.
4. Marker «Impact Dissolve – <clip>» σε κάθε αλλαγή. Τα κλιπ έχουν περιθώριο στις άκρες, ώστε να χωράει το dissolve.
5. **Τέλος:** drone με κίνηση στα τελευταία ~6″, πάνω στον ήχο του τελευταίου χορού, που συνεχίζει και σβήνει (fade 3″). Ο ήχος του πρώτου χορού μπαίνει με fade 1″.
6. Η ροή μπορεί να ξεπεράσει την 1.5 ώρα (σε μία βάφτιση έφτασε 1:51). Αυτό είναι αναμενόμενο.
7. Τα κλιπ χορού ήταν **1080p25**: στο XML παίρνουν `src_rate=25` και **Scale 200%**.

# ΦΑΣΗ Ε — XML για Premiere

## 7.1 Προδιαγραφές (FCP7 xmeml v4)

- `<xmeml version="4">`, ένα `<sequence>`, `timebase 25`, `ntsc FALSE`, format 3840×2160, square pixels, `fielddominance none`, ήχος 48 kHz/16 bit, `numOutputChannels 2`.
- **Χρόνοι στο sequence σε καρέ των 25 fps**: `fr(s) = round(s × 25)`.
- **`<file>`**: ορίζεται πλήρως μία φορά και μετά αναφέρεται με `<file id="…"/>`. `id = "f-" + όνομα αρχείου`.
  - `pathurl = "file://localhost" + διαδρομή`, με escape **μόνο** για κενό (`%20`), `(` (`%28`) και `)` (`%29`). Τα ελληνικά μένουν ως έχουν σε UTF-8 και το Premiere τα διαβάζει σωστά.
  - `rate` του file = πραγματικό fps της πηγής (50 ή 25). `duration` σε καρέ πηγής. `<media>` με video (w, h) και audio (2 κανάλια).
- **`<clipitem>` χωρίς αλλαγή ταχύτητας:** `in`/`out` σε **καρέ sequence** (25). `out = in + (end − start)`.
- **`<clipitem>` με Time Remap (slow-mo):** το Premiere διαβάζει `in`/`out` σε **καρέ ΠΗΓΗΣ** (π.χ. 50p): `in = round(src_in × src_rate)`, `out = in + round((end − start) × speed × src_rate / 25)`. Μπαίνει και φίλτρο `Time Remap` (`effectid timeremap`) με `speed = speed × 100`, `variablespeed 0`, `reverse FALSE`, `frameblending FALSE`.
- **Κλιπ με πλάτος < 3840:** φίλτρο `Basic Motion` (`effectid basic`) με `scale = 3840 / w × 100` (1080p → 200). Είναι το μόνο «εφέ» που επιτρέπεται.
- **Ήχος:**
  - Το clipitem δείχνει στο αρχείο: για ήχο κάμερας το ίδιο το video file, με `<sourcetrack><mediatype>audio</mediatype><trackindex>1</trackindex>`.
  - Η μουσική μπαίνει σε δύο tracks (srctrack 1 και 2).
  - `outputchannelindex` εναλλάξ 1/2 ανά track.
- **Fades ήχου:** `<transitionitem>` με `Constant Power` (`effectid KGAudioTransCrossFade3dB`). Για fade-in `alignment start-black` (start, start + d). Για fade-out `end-black` (end − d, end).
- **Markers:** `<marker><name>…</name><in>καρέ</in><out>-1</out></marker>` μέσα στο sequence.
- **Tracks:**
  - Highlights: V1 εικόνα · A1/A2 μουσική · A3 ήχος των film σκηνών.
  - Ροή: V1 · V2 (cutaways/δικάμερο) · A1 ήχος τελετής · A2/A3 μουσική.
- Αντιγράφουμε το τραγούδι σε `<βάφτιση>/music/` και το XML δείχνει εκεί.

## 7.2 Ο writer (πλήρης, ~65 γραμμές)

```python
"""Minimal FCP7 xmeml writer for Premiere (4K 25p sequences; 4K50 and 1080p25 sources)."""
import os
from xml.sax.saxutils import escape
FPS = 25
fr = lambda s: int(round(s * FPS))
url = lambda p: "file://localhost" + p.replace(" ", "%20").replace("(", "%28").replace(")", "%29")
class Seq:
    def __init__(s, name): s.name, s.files, s.vtracks, s.atracks, s.markers, s.n = name, set(), {}, {}, [], 0
    def fileref(s, path, dur_s, rate, video, w=3840, h=2160):
        fid = "f-" + os.path.basename(path)
        if fid in s.files: return f'<file id="{escape(fid)}"/>'
        s.files.add(fid)
        mx = (f'<video><samplecharacteristics><rate><timebase>{rate}</timebase><ntsc>FALSE</ntsc></rate><width>{w}</width><height>{h}</height>'
              f'<pixelaspectratio>square</pixelaspectratio></samplecharacteristics></video>' if video else "")
        mx += '<audio><samplecharacteristics><depth>16</depth><samplerate>48000</samplerate></samplecharacteristics><channelcount>2</channelcount></audio>'
        return (f'<file id="{escape(fid)}"><name>{escape(os.path.basename(path))}</name><pathurl>{escape(url(path))}</pathurl>'
                f'<rate><timebase>{rate}</timebase><ntsc>FALSE</ntsc></rate><duration>{int(dur_s * rate)}</duration><media>{mx}</media></file>')
    @staticmethod
    def timeremap(speed):
        if abs(speed - 1) < 1e-6: return ""
        return ('<filter><effect><name>Time Remap</name><effectid>timeremap</effectid><effectcategory>motion</effectcategory><effecttype>motion</effecttype>'
                '<mediatype>video</mediatype><parameter authoringApp="PremierePro"><parameterid>variablespeed</parameterid><name>variablespeed</name>'
                '<valuemin>0</valuemin><valuemax>1</valuemax><value>0</value></parameter><parameter authoringApp="PremierePro"><parameterid>speed</parameterid>'
                f'<name>speed</name><valuemin>-100000</valuemin><valuemax>100000</valuemax><value>{speed * 100:.4f}</value></parameter>'
                '<parameter authoringApp="PremierePro"><parameterid>reverse</parameterid><name>reverse</name><value>FALSE</value></parameter>'
                '<parameter authoringApp="PremierePro"><parameterid>frameblending</parameterid><name>frameblending</name><value>FALSE</value></parameter></effect></filter>')
    @staticmethod
    def fit(w):
        if w >= 3840: return ""
        return ('<filter><effect><name>Basic Motion</name><effectid>basic</effectid><effectcategory>motion</effectcategory><effecttype>motion</effecttype>'
                f'<mediatype>video</mediatype><parameter authoringApp="PremierePro"><parameterid>scale</parameterid><name>Scale</name><valuemin>0</valuemin>'
                f'<valuemax>1000</valuemax><value>{3840 / w * 100:.1f}</value></parameter></effect></filter>')
    def video(s, track, path, dur_s, start, end, src_in, speed=1.0, src_rate=50, w=3840, h=2160):
        st, en = fr(start), fr(end); s.n += 1
        if abs(speed - 1) < 1e-6: i0 = fr(src_in); i1 = i0 + (en - st)                       # sequence frames
        else: i0 = int(round(src_in * src_rate)); i1 = i0 + int(round((en - st) * speed * src_rate / FPS))   # source frames
        s.vtracks.setdefault(track, []).append((st,
            f'<clipitem id="v{track}-{s.n}"><name>{escape(os.path.basename(path))}</name><enabled>TRUE</enabled><duration>{int(dur_s * FPS)}</duration>'
            f'<rate><timebase>{FPS}</timebase><ntsc>FALSE</ntsc></rate><start>{st}</start><end>{en}</end><in>{i0}</in><out>{i1}</out>'
            f'{s.fileref(path, dur_s, src_rate, True, w, h)}{s.timeremap(speed)}{s.fit(w)}</clipitem>'))
    def audio(s, track, path, dur_s, start, end, src_in, srctrack=1, fade_in=0, fade_out=0, video_src=False, src_rate=50, w=3840, h=2160):
        st, en = fr(start), fr(end); s.n += 1; i0 = fr(src_in); i1 = i0 + (en - st)
        item = (f'<clipitem id="a{track}-{s.n}"><name>{escape(os.path.basename(path))}</name><enabled>TRUE</enabled><duration>{int(dur_s * FPS)}</duration>'
                f'<rate><timebase>{FPS}</timebase><ntsc>FALSE</ntsc></rate><start>{st}</start><end>{en}</end><in>{i0}</in><out>{i1}</out>'
                f'{s.fileref(path, dur_s, src_rate if video_src else FPS, video_src, w, h)}<sourcetrack><mediatype>audio</mediatype><trackindex>{srctrack}</trackindex></sourcetrack></clipitem>')
        def trans(a, b, align):
            return (f'<transitionitem><rate><timebase>{FPS}</timebase><ntsc>FALSE</ntsc></rate><start>{a}</start><end>{b}</end><alignment>{align}</alignment>'
                    '<effect><name>Constant Power</name><effectid>KGAudioTransCrossFade3dB</effectid><effectcategory>Dissolve</effectcategory>'
                    '<effecttype>transition</effecttype><mediatype>audio</mediatype></effect></transitionitem>')
        L = s.atracks.setdefault(track, [])
        if fade_in: L.append((st - 0.5, trans(st, st + fr(fade_in), "start-black")))
        L.append((st, item))
        if fade_out: L.append((en - fr(fade_out) + 0.5, trans(en - fr(fade_out), en, "end-black")))
    def marker(s, t, name): s.markers.append(f'<marker><name>{escape(name)}</name><comment></comment><in>{fr(t)}</in><out>-1</out></marker>')
    def write(s, out, total_s):
        total = fr(total_s)
        vt = "".join("<track>" + "".join(x[1] for x in sorted(s.vtracks[k], key=lambda x: x[0])) + "</track>" for k in sorted(s.vtracks))
        at = "".join("<track>" + "".join(x[1] for x in sorted(s.atracks[k], key=lambda x: x[0])) + f"<outputchannelindex>{1 + (k - 1) % 2}</outputchannelindex></track>" for k in sorted(s.atracks))
        xml = ('<?xml version="1.0" encoding="UTF-8"?>\n<!DOCTYPE xmeml>\n<xmeml version="4"><sequence id="seq-1">'
               f'<name>{escape(s.name)}</name><duration>{total}</duration><rate><timebase>{FPS}</timebase><ntsc>FALSE</ntsc></rate>{"".join(s.markers)}<media>'
               '<video><format><samplecharacteristics><rate><timebase>25</timebase><ntsc>FALSE</ntsc></rate><width>3840</width><height>2160</height>'
               f'<pixelaspectratio>square</pixelaspectratio><fielddominance>none</fielddominance></samplecharacteristics></format>{vt}</video>'
               '<audio><numOutputChannels>2</numOutputChannels><format><samplecharacteristics><depth>16</depth><samplerate>48000</samplerate></samplecharacteristics></format>'
               f'{at}</audio></media></sequence></xmeml>\n')
        open(out, "w").write(xml)
```

## 7.3 Επαλήθευση του XML (πάντα, πριν την παράδοση)

Παρσάρουμε το XML που γράψαμε και ελέγχουμε:

1. Κάθε `pathurl`, αφού γίνει unquote, **υπάρχει στον δίσκο**.
2. Για κάθε clipitem: `in ≥ 0`, `end > start`, και `out ≤` διάρκεια πηγής. Το όριο είναι σε καρέ πηγής για time-remapped, αλλιώς σε καρέ sequence, δηλαδή `duration × 25 / rate`.
3. **Καμία επικάλυψη** μέσα στο ίδιο track (`start ≥ end` του προηγούμενου).

Τυπώνουμε πλήθος clipitems, πλήθος files, missing και bad. Παραδίδουμε μόνο με «missing 0, bad []».

# ΦΑΣΗ ΣΤ — Preview χαμηλής ανάλυσης

- **Εικόνα:** το V1/V2 ισοπεδώνεται σε τμήματα (σε κάθε διάστημα ορατό είναι το ψηλότερο track). Κάθε τμήμα αποδίδεται ξεχωριστά:

```bash
ffmpeg -ss <src> -t <dur*speed+0.3> -i <clip> -map 0:v:0 -vf "scale=960:540,setpts=PTS/<speed>,fps=25" -frames:v <n> -an -c:v libx264 -crf 26 -preset veryfast -pix_fmt yuv420p seg.mp4
```

  Το **όνομα του τμήματος βγαίνει από το περιεχόμενο** (`<clip>_<src>_<frames>_<speed>.mp4`), ώστε ένα νέο σχέδιο να μην ξαναχρησιμοποιεί παλιό τμήμα. Η αρίθμηση ανά θέση είχε προκαλέσει λάθος, γιατί έμεναν παλιά τμήματα. Μετά γίνεται `concat` με `-c:v copy`.
- **Ήχος:** κάθε κομμάτι μπαίνει στη θέση του με `adelay`, μαζί με τα fades του (`afade`). Μετά `amix=normalize=0` και `alimiter=limit=0.9`, AAC 160k, `+faststart`.
  - Ήχος κάμερας από κομμάτια που είναι πολύ δυνατά (χοροί, κλάμα): −5 dB. Μουσική: −2 έως −3 dB.
- **Έλεγχος του preview:** διάρκεια = διάρκεια sequence, στάθμη (`volumedetect`, στόχος γύρω στα −14 έως −16 dB μέσο), και δείγμα καρέ σε διάφορα σημεία.
- Αρχεία πάνω από ~500 MB δεν ανεβαίνουν για απομακρυσμένη προβολή (κινητό ή web). Το λέμε στον μοντέρ: «φαίνεται μόνο στο desktop app».

## 10. Παγίδες που συναντήθηκαν

- **T7 / T7 1:** η διαδρομή αλλάζει. Τη βρίσκουμε κάθε φορά.
- **Κάμερα στο πάτωμα στην αρχή κάθε κλιπ:** ποτέ ένα καρέ. Για κλιπ μοντάζ ξεκινάμε μετά τα πρώτα δευτερόλεπτα.
- **Ρολόι κύριας κάμερας:** υπολογίζεται κάθε φορά και επιβεβαιώνεται με τη δεύτερη κάμερα. Προσοχή στη θερινή/χειμερινή ώρα.
- **Η μεταγραφή μπορεί να έχει διαφορετική μορφή** (λίστα segments ή dict με `segments`). Ο κώδικας ανάγνωσης πρέπει να δέχεται και τα δύο.
- **ffmpeg χωρίς drawtext:** labels με OpenCV ή ImageMagick.
- **Διαδρομές με κενά και παρενθέσεις στο XML:** escape `%20 %28 %29`.
- **Time-remapped clips:** in/out σε καρέ πηγής, αλλιώς το slow-mo παίζει λάθος κομμάτι.
- **1080p σε 4K:** Scale 200%, και `src_rate` το πραγματικό fps (25 ή 50).
- **Τμήματα preview ονομασμένα ανά θέση:** επαναχρησιμοποιούσαν παλιά τμήματα. Τα ονομάζουμε από το περιεχόμενο.
- **Ο δίσκος αποσυνδέθηκε στη μέση μιας αντιγραφής:** ελέγχουμε το mount πριν από κάθε βήμα και δεν αφήνουμε μισά αρχεία.
- **Drone offline μετά την εισαγωγή του XML:** Link Media με Align Timecode ξετσεκαρισμένο.
- **Το Premiere έχει ανοιχτό άλλο project ή άλλη συνεδρία κρατά τη γέφυρα:** δεν το αγγίζουμε.
- **Μεγάλα preview (>500 MB):** μόνο στο desktop.

## Παράρτημα Γ — Σειρά εργασιών (checklist)

1. Βρες τον φάκελο (T7 / T7 1). Κατάγραψε κάμερες, πλήθη, formats, κλιπ ≥ 60″, και αν υπάρχει mic.
2. Υπολόγισε τα offsets ρολογιών και επιβεβαίωσέ τα σε 2–3 σημεία.
3. Βγάλε 3 καρέ ανά κλιπ → contact sheets → ταξινόμηση με το μάτι → έλεγχος διπλών/χαμένων → μετακίνηση → έλεγχος πριν/μετά → ευρετήριο + contact sheets ανά φάκελο.
4. `media.json` → μεταγραφή masters (2 περάσματα) → μετρήσεις κίνησης → drone windows → συγχρονισμός B (και mic).
5. Highlights: picks ανά slot → αυτόματα παράθυρα → φύλλα ελέγχου → διορθώσεις με το μάτι → film slots.
6. Ροή: σχέδιο (M/F/B/SEC) από τη μεταγραφή → σημεία κοπής στα ήσυχα σημεία → γέφυρες μόνο όπου η κάμερα ήταν σβηστή → cutaways και δικάμερο → τέλος (και χοροί) → αυτόματοι έλεγχοι.
7. XML (highlights + ροή) → επαλήθευση (missing 0 / bad []).
8. Preview → έλεγχος διάρκειας, στάθμης, καρέ.
9. Παράδοση: πίνακας + τι να προσέξει (π.χ. offline drone, κουνημένα αλλά καλά πλάνα) + markers.
10. Όταν επιστρέψει διορθωμένο μοντάζ: σύγκριση κλιπ προς κλιπ → νέοι κανόνες.

## Παράρτημα Δ — Ροή χωρίς ή με mic: σύνοψη διαφορών

  - Όταν ζητηθεί, ξεχωριστός φάκελος για τις στιγμές που **η νύφη μιλάει στην κάμερα** (μόνο όπου κοιτάει τον φακό).
  - Μπορεί να είναι γάμος **και** βάφτιση την ίδια μέρα. Τότε χωρίζονται σε ξεχωριστές ενότητες.
- **Σημεία της τελετής που κρατάμε:** αρραβώνες / δαχτυλίδια, στέφανα, Απόστολος, Ευαγγέλιο, κοινό ποτήριο, «Ησαΐα χόρευε», απόλυση, ευχές.
- **Η εκκλησία μένει ολόκληρη.** Κόβουμε μόνο κουβέντα εκτός τελετής και μεγάλες σιωπηλές ευχές, ποτέ το ίδιο το τυπικό.
- **Τοπίο:** δείχνουμε πολύ τον τόπο, με αργό άνοιγμα πριν εμφανιστούν άνθρωποι και φυσικούς ήχους από κάτω.
- **Ήχος:** **χωρίς μουσική** όπου μιλάει ο παπάς, στην είσοδο του ζευγαριού και στο πάρτι.
- **«Να μην πετάξουμε υλικό»:** κάθε στημένη ομαδική και κάθε πλάνο του πάρτι μπαίνει κάπου. Ό,τι περισσεύει από το πάρτι πάει σε μουσικό μοντάζ.
- **Τίτλος:** αφήνουμε καθαρό πλάνο και marker για τα ονόματα. Τα γραφικά τα κάνει ο μοντέρ.
- **10-bit Sony** (4:2:2 / HEVC) δεν περνάει από εργαλεία που θέλουν 8-bit 4:2:0. Χτίζουμε απευθείας FCP7 XML πάνω στα αρχικά αρχεία.
